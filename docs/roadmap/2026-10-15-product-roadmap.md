## 2. 七个阶段

| 阶段 | 用户能得到什么 | 主要交付物 | 完成标准 |

## 3. 各阶段的关键边界

### 阶段 1：方案收敛与开发准备

本阶段收敛产品、页面、视觉、技术与验证规格，准备必要的工具、skills 和仓库。以下工作在进入对应开发前落实，实际完成情况见交接文档：

1. 将客户端状态/路由、后端、数据库、访问方式及数据策略从建议收敛为具体决策，保留依据与日期。
2. 确定首批实际设备、浏览器与版本，按当前Web优先顺序验证；原生恢复时补齐设备条件。
3. 核对工具链、可用模型账号、地域与权限，明确试验允许的费用范围。
4. 统一规格中的视觉角色、操作语义和数据行为；未来供应商能力由阶段 3 实测决定。

普通工程细节按既定规范推进。设备、账号权限、可接受费用和确实影响产品行为的取舍，在需要时集中确认，不把每个按钮尺寸都变成单独的许可请求。

### 阶段 2：工程底座与组件系统

按仓库约定建立 apps/client/、services/api/ 和 deploy/ 的必要内容。完成配置读取、数据库迁移、认证和最小健康检查；供应商长期密钥只由服务端持有。

把视觉规范落实为共享主题及按钮、输入、状态提示、导航、话语、反馈条目和伙伴组件，预览覆盖深浅色、大字号和异常。首批页面包含访问、主页与个人设置；通话相关组件预览使用明确的测试状态。

建立有用的格式、静态分析、核心测试和构建检查，记录本地运行方法。此阶段的构建成功只证明工程可构建，不作为真实语音或学习效果的证据。

### 阶段 3：真实语音练习

使用真实服务完成“本人开始 → 授权 → 建连 → 连续交流 → 自然插话 → 结束 → 查看最终文字和用量”。当前先验证桌面与手机浏览器的真实音频路径，按实际结果形成Web支持矩阵。原生恢复时重新验证相应音频路径；Web成功不能代表原生成功。

按[验证计划](../validation/2026-10-15-validation-plan.md)观察基础用户的停顿、外放回声、自然插话、旧回复取消、实际播放上下文、断线和后台暂停。界面显示对应真实媒体状态，明确本地停止和上游终止的区别。

产出供应商、模型、地域、协议、能力和实际费用的选型记录。当前千问 WebRTC 路线是首轮候选；不能满足关键要求时，依据失败证据评估受控 RTC 或服务端持有上游连接的方案。阶段结果必须明确强制结束与硬额度是否可信；需要硬上限时，缺失该能力的路线不能通过相应准入。

2026-10-20补充：按[收尾与反馈依据契约](../architecture/2026-10-20-practice-completion-and-review-contract.md)区分正常结束和立即释放，验收最后一句及打断前缀收尾。正常反复练习还必须证明未知连接有可核验的退出路径，覆盖客户端消失和信令答案丢失；无退出路径的候选仅可另行授权受控技术实验。此门槛与金额硬上限分开，不以接受软额度替代。

### 阶段 4：完整学习闭环

补齐自由聊天与日常话题、个人难度、英文字幕、中文提示和按需辅助。完成会后反馈、逐句重练、记录详情与级联删除。

反馈保存真实引用、输入版本、评价资格和建议类型，允许零至三项；不提供转写纠错入口，不输出无音频评测支持的发音分数。一级重练拥有自己的身份、转写和用量，返回原普通练习复盘；依据本次话语分别评价原意及目标问题，允许不同说法，未展示目标/证据不足不当作成功。通过持久任务、幂等提交与平台补交策略处理保存、反馈失败和进程重启。

阶段验收至少覆盖：正常结束收尾、无可评价内容、无confidence但可理解的最终文字、反馈失败重试、两次独立重练、不同措辞与目标未展示、拒绝二次派生、重复结束、删除范围并发变化与晚到结果。普通练习删除覆盖全部一级重练；删除正文不解除未知媒体占用。形成完整体验后，再扩大试用覆盖。

### 阶段 5：可靠性与成本控制验收

集中验证断网、业务后端失联、供应商超时、设备切换、锁屏、应用被杀、并发启动和重复事件。检查历史设置快照、跨账号访问、退出清理与删除后晚到结果。

对照供应商账单检查语音、反馈、辅助与重练用量，区分估算、客户端观测和可信结算。验证准入、并发及已建媒体会话的终止机制；未能证明的硬费用上限如实记录，并完成是否接受相应试用边界的决定。

进行数据库备份恢复、删除清单重放和失败任务恢复演练。产物包含复现步骤、证据、修复与复测结果；遗留限制反映在界面、支持范围和运行说明中。

2026-10-25已补[人工备份生成与离线检查](../architecture/2026-10-25-backup-bundle.md)，同快照dump/删除清单、真实隔离恢复及快照后删除的最新清单重放见[证据](../development/2026-10-25-backup-bundle-verification.md)。自动调度、异地实时删除日志、保留期执行、可信供应商终止与费用仍未完成，阶段5保持进行中。

### 阶段 6：Web交付与朋友试用

完成Web的HTTPS、前后端环境配置、数据库迁移与部署流程。目标手机的原生签名、构建与分发暂停，恢复时单独安排。先服务受邀使用者；面向公众或商店的发布范围与要求在决定公开发行时另行确认。

在真实大陆 Wi-Fi、移动数据、外放和常用耳机上跑通完整流程。部署具备健康状态、脱敏错误和用量观察，并完成一次可执行的回退验证。

让不同水平的实际使用者独立进入、完成练习并查看复盘。重点收集抢话、听不懂、不会求助、反馈不准确、恢复困难和内容丢失，而不只收集配色喜好。所有问题按影响排序，保留修复后的复测结果。

### 阶段 7：持续使用与成熟维护

先根据实际对话改善接话、等待、语速、追问和反馈，消除重复出现的使用障碍。功能扩展依据真实需求逐项进入，不为增加页面数量引入完整课程、社交或人物系统。

学习积累可按需从“保存有价值的表达、复习常见问题、跟踪练习历史”中选择最有效的一项；它们对应总纲后续需求 R13，不自动变成当前版本全部必交功能。专项发音评测 R14、丰富人物与激励 R15 仍单独选型和验收。

维护工作包含依赖升级、数据库迁移、备份检查、费用趋势、问题定位和版本回退。持续使用记录建议跨越至少两周，覆盖日常使用与异常恢复；时间跨度仅是观察起点，不能单独证明体验成熟或学习有效。

## 4. 成熟标准

| 维度 | 可检查的依据 |
| --- | --- |
| 使用价值 | 不同水平用户能够独立开始、聊完、理解反馈并重练，实际使用中能指出收获与问题 |
| 语音体验 | 支持的设备与网络有实测记录，接话、停顿、插话和回声达到已确定目标；没有用平均值隐藏失败 |
| 反馈可信 | 抽查可以定位原话、核实解释和原意；不凑错误数量，不把可选润色当成错误 |
| 数据可靠 | 账号隔离、幂等、版本、重启恢复、备份恢复及删除演练通过，无已知数据泄露或内容复活问题 |
| 费用清楚 | 实际用量能核对，准入和终止能力有证据，费用异常可以定位；对未结算信息有明确状态 |
| 交付稳定 | 支持矩阵清楚、主要流程可回归、发布和回退可执行，有运行说明和真实缺陷记录 |
| 维护可持续 | 一个人可以依照文档更新、部署、恢复和排查，架构复杂度与小范围使用匹配 |

跨用户访问、用户结束后仍未受控拾音、不可恢复的主要记录丢失、关键设备无法完成语音或无法解释的持续费用，均属于需要优先解决的问题，不能在未明确限制和处理的情况下称为成熟版本。

## 6. 进度与排期方式
