# 浏览器传输输出压制

2026-10-30。自然插话需要在用户开始说话时压制 AI 输出，同时保留上行语音；此前浏览器传输只有静音输入、恢复播放和结束整个媒体连接，没有独立输出压制能力。此次新增传输层原语，未将其接入千问单轮协议或用户页面，也未开放正式语音。

## 契约与边界

- `holdPlayback()` 仅在活动连接中工作：同步将浏览器音频元素静音，不停止或禁用输入轨；重复调用保持原状。抑制已有 `playing` 事件对外的错误播放观察，并让已经等待的 `resumePlayback()` 尽快以 `playback_held` 结束。抑制期间普通恢复播放不会解除输出压制。
- `releasePlayback()` 是唯一显式解除动作，恢复压制前的元素静音状态，再按现有有界播放器逻辑尝试播放；不能用于证明迟到的旧音频已清除，调用方必须先解决响应取消、上下文和旧音频安全问题。未压制、未激活、收尾、已关闭和设备设置异常分别返回稳定状态；设置失败会停止本地媒体而非假装成功。
- 新能力经 Dart Web 桥接暴露；原生实现仍为 unsupported。音频元素静音是浏览器本地控制，不能推断设备最后实际发出的样本、听者已听到的文字、供应商取消、上下文截断或计费终止。压制功能不会自动触发、不发 `response.cancel`，现有单轮协议对第二次发言仍安全停止。

## 本机回环

使用当前生产 `realtime_transport.js`、macOS Edge 156.0.4314.50 与两个本机 PeerConnection；输入和远端输出均为合成音调，本地输出元素音量固定为零，不申请物理麦克风、不调用模型。实际页面显示：连接及激活成功；压制前音频元素 `muted=false`，压制后为 `true`；输入音轨仍 `enabled=true`、`live` 且仍是 sender 的轨道。压制约 1.2 秒期间接收端入站字节从 4,104 增至 8,964，接收端静音分析支路有 24 次采样超过 0.001 阈值。普通恢复返回 `playback_held` 且元素仍静音；显式释放成功后恢复 `muted=false`。无真实扬声器播放验证。

页面输出为人工转录，见[结果](evidence/2026-10-30-output-hold-loopback.json)和[实验页面](evidence/2026-10-30-output-hold-loopback.html)；页面加载的传输脚本副本与仓库源码 SHA-256 相同。统计证明本次本机浏览器的上行保持与元素属性变化，不证明实际声音被准确切断或符合全部浏览器时序。实验标签、临时服务及目录已清理。

## 验证与后续

节点测试先复现缺失输出压制接口及压制后旧播放请求未及时结束，修复后覆盖输入轨独立、需要显式释放、旧观察抑制、音轨迟到、设置异常和收尾等；Dart 编译桥测试先因缺接口失败，现覆盖调用及同步异常转换。最终 Flutter 全量 1513 项通过、10 项专用测试跳过；Node 全量 83 项通过；Flutter 静态分析、5 个 Dart 文件格式检查及 Web release 构建通过。构建产物中的传输脚本与源码 SHA-256 一致；既有千问播放探针的 6 项测试也通过。本轮未重跑无关后端全量。

下一步仍需在真实供应商及浏览器上验证 VAD 触发、上游取消和旧音频处理，解决安全上下文恢复、可信远端退出和设备输出，随后才可考虑将能力接入真实多轮和插话；当前不能把此原语标为自然插话已完成。
