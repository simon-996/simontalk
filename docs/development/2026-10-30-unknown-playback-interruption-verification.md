# 未知播放边界的受控中断

2026-10-30。千问 WebRTC 实验中回复取消后仍观察到远端非静音采样，不能将取消终态视作旧音频清空；同时目前没有可验证的已播文字边界。本批为默认未开放的千问候选增加一次受限中断，不将未知边界写成零或已播前缀。

## 实现

- 媒体协调器增加 `quarantineUnknownResponse` 能力：只接受活动连接原确认通道、存在且所有播放状态未知的助手回复；如果当前或历史修订已有可信播放证据，包括已确认的零位置，拒绝进入此未知路径。先压制旧输出，固定不延长的尾部截止，保留用户上行；此路径不调用 `freezeResponse`、不写冻结前缀或制造设备输出位置。
- 隔离期间禁止生成上下文快照、恢复播放及普通新回复，忽略该回复后续的播放对齐更新；原回复的取消由既有受保护通道最多发送一次，超过原截止不再发送。用户输入及旧回复期限内的文字事实仍可接收。进入正常结束后可以按原规则保留已登记用户项的最终识别，而不会在结束时补造未知回复的冻结边界。
- 千问受限协议只在已有明确绑定、尚未结束的原回复上接收一个新语音项；先由归一化器验证事件和重放身份，再隔离旧输出、登记新用户项并发送一次取消。该项须依次停止、提交和最终识别；接受匹配原回复的 `cancelled` 或竞争完成的 `completed`，不发送第二个 `response.create`。第三个语音项、无绑定回复、错误项或无效顺序继续失败关闭。
- 在输出压制或取消过程同步重入结束时，用户已开始的语音项先登记再冻结；如果压制阶段换号、失败或同步重入则立即关闭，不发送越界取消。上下文确认不能解除未知音频隔离。

## 验证与边界

协议单测和真实媒体协调器配替身传输测试覆盖一次中断、同项最终文字、取消去重、错误或冲突事件不能触发副作用、重复事件幂等、先停止再提交、立即结束竞态、前缀未知、历史对齐记录、超时、换号、压制失败、重入和正常结束保存。相关测试先复现缺失能力及竞态，修复后通过。真实千问先前两次 WebRTC 实验只验证独立探针的事件与取消，**没有运行本次更新后的 Dart 协议或媒体协调器**，见[先前实验](2026-10-30-qwen-webrtc-interruption-verification.md)。

本批未调用模型、申请麦克风或修改后端/数据库；相关目标测试 98 项通过，Flutter 全量 1544 项通过、10 项专用测试跳过，Node 83 项通过，静态分析、7 个 Dart 文件格式、`git diff --check` 及 Web release 构建通过（33.5 秒，未运行 Wasm dry-run）；构建传输脚本与源码哈希一致。该候选仍保持输出隔离，不能生成下一轮回复，也没有可信远端退出、音频清空或听觉/文字对齐证据；默认协议工厂和后端语音准入仍关闭。下一步是对当前真实控制器/协议的受控 WebRTC 行为补实测，并解决旧音轨隔离恢复、上下文和远端退出；正式入口开放前还需清晰呈现中断后不能继续回复的状态；手机及实际人耳验收仍待完成。
