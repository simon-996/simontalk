# 练习准备登记验证

日期：2026-10-17（Asia/Shanghai）。本地功能分支；无供应商调用、推送或外部部署。

## 已落实

- 创建登记按本人身份与UUID幂等键持久保存；规范化输入不同返回409，同key重放原快照。临时难度覆盖与原偏好分开保存，不改个人设置。
- User行锁串行化同账号创建/取消；部分唯一索引限制全部未终结状态。锁后重新鉴权，等待期间被撤销/禁用返回401。
- 本人读取、取消仅限未建连created；已connecting不能取消成“结束”。重复取消保持时间与结果，原创建key仍重放已取消记录。
- 真实策略固定拒绝；无环境启用开关、无上游HTTP或媒体调用。没有练习按钮、假聊天、转写或用量。

## 自动验证

最初默认拒绝测试观察到404而失败，再实现路由与用例。

`uv run pytest -q` **62项通过**（8.61秒），包含原42项账号回归与20项准备登记检查。补强数据库实际锁等待观测后，再跑20项定向测试全部通过（2.67秒）。Ruff检查/格式通过；`alembic check`无新增迁移差异，head为`2acda42539f0`。

关键证据：

- 同key并发返回同一记录；不同key并发一个201、一个409；直接绕过用例插入第二条开放记录仍被PostgreSQL唯一索引拒绝。
- 初始难度缺失不能通过临时覆盖绕过；快照不随偏好或准入策略变化而重写；新create_app与独立引擎在默认关闭策略下仍重放已有登记。
- 持有User锁、首次身份检查后提交撤销/禁用，等待请求最终401且无写入。取消等待练习行锁期间提交connecting，取消返回409并保留占用。测试通过pg_stat_activity确认实际FOR UPDATE锁等待，不仅依赖查询前回调。
- 他人读取/取消均404；Web保持Origin、CSRF、X-Account-ID保护，CORS只新增Idempotency-Key允许头。额外owner/供应商输入被422拒绝。

独立复核未发现P1/P2；建议的锁竞争与跨实例证据已补充。退出与已经通过认证的在途写入可能并行，契约明确该边界；下一阶段真实建连必须重新鉴权与准入。
