# 受主管约束的消息泵会话验证

新增内部 `run_pump_session`，在既有主管的已配置连接中创建真实消息泵，分别单读上游事件与专属下游 PCM/控制。任一侧失败、客户端 stop、取消或主管关闭时执行本地关闭；下游只接受既有严格 PCM 中继支持的内容。主管仍负责运行期身份复验及 unknown 收尾。

开发中发现三类竞争：正常 stop 会先关闭上游，接收循环可能早于停止处理完成并误报断线；重复将同一个下游交给另一会话会造成并发读取；下游发送任务忽略取消时，读取循环可能已经结束但发送仍在途。定向测试均先复现失败。现由已经验证的 stop 标记处理关闭竞争；占用期间拒绝重复下游；分别追踪泵内迟到发送和会话任务，在任务实际结束前保留有界名额和下游归属。容量耗尽且拒绝关闭任务也满时，调用方仍负责关闭未接管的下游；已关闭的 socket 不得重复使用。停止或本地关闭都不是远端已退出的证据。

本轮新增 10 项生命周期测试：合成 PCM 和上游事件、stop、输入错误、配置失败、启动和运行中取消、下游发送失败、运行期模拟身份失效、忽略取消的接收和发送、重复下游。测试使用真实主管、连接包装和消息泵，底层 socket、身份复验及 unknown 回写为替身。包含现有消息泵、音频过滤、发送、中继、握手和安全连接等共 181 项后端目标通过；Ruff 和 4 个 Python 文件格式检查通过。未运行真实数据库、供应商、浏览器或物理麦克风，未重跑完整后端/客户端。

此函数还没有公开 WebSocket 路由，也没有浏览器握手、身份核验和 claim 创建接线；正式语音准入仍关闭。需要后续在独立 PostgreSQL 上验证真实身份撤销和 unknown 回写，以及实际浏览器对端关闭和媒体链路；播放前缀、多轮上下文和可核验上游退出仍待解决。
