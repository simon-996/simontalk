# 浏览器设备中断与练习记录验证

2026-11-26（Asia/Shanghai）。验证正式练习页的 WebSocket 媒体路径，语音准入保持关闭。

麦克风暂时无法提供输入时，浏览器可触发 `mute`，音轨仍为 `live`。现在采集在启动和转交工作线程 PCM 前都检查音轨及输入上下文状态，收到音轨 `mute` 或 `ended` 会停止会话。应用内的静音开关仍按原协议控制上行。输出上下文完成初始化之后，无论有无正在播放的回复，只要变为非运行状态，就停止麦克风、播放和同源 WebSocket。输出状态在激活和发送前也会检查，覆盖状态先变化、事件后到的情况。[Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/#media-flow) · [Web Audio API](https://www.w3.org/TR/webaudio-1.0/#dom-baseaudiocontext-state)

第一次 Chrome 联测观察到本机媒体已经释放，页面仍显示“等待保存回执”。修复后，没有主动保存请求的中断显示具体原因，也能进入“查看本次记录”。原有保存中、已封存和保存失败的状态仍取实际保存结果。关闭本地媒体后，服务器继续保留未知终止占用。

## 联测结果

| 场景 | Chrome 与 PostgreSQL 结果 |
| --- | --- |
| AI 播报时麦克风输入中断 | 向虚拟音轨注入来源 `mute`，停止仍在排程中的播报、释放音轨及两个音频上下文。页面显示麦克风中断，旧回复无 `settled`。 |
| 两轮之间输出暂停 | 第一轮正常结算后调用真实 Chrome `AudioContext.suspend()`。页面显示播放失败，麦克风、两个音频上下文和连接均释放。 |

两个场景可从停止页面打开原练习保存状态，显示仍有连接与用量待核对。没有额外回复、尾句提交或固化记录。服务端练习是 `interrupted`，连接仍是 `unknown`，终止核验为 `blocked`、0 次。

Node 全量 146 项、Flutter 全量 1,608 项（10 项专用夹具跳过）、Chrome 158 与隔离 PostgreSQL 17.11 正式页联测 10 项通过。Flutter analyze、Dart 格式和 Python 联测 Ruff 通过。两份媒体脚本与隔离及正式 Web 包逐字节一致，正式 Web 包字体保留 30,890 个映射。临时测试库已移除，默认开发库仍健康运行。源码与文档保留在本地工作区。
