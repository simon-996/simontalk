# Web Audio 静音输出时钟观察

2026-10-29（北京时间），在 macOS 26.6.2 和 Microsoft Edge 156.0.4314.50 上，用本地临时页面分别做一次完整播放和一次中途停止。页面在内存生成 1.5 秒、48 kHz 单声道信号，经零增益连接输出；没有使用麦克风、调用模型或保存音频。页面报告的数值由浏览器可访问性文本人工转录到[证据](evidence/2026-10-29-webaudio-output-clock.json)，不是自动采集，也不是多设备统计。

完整播放中，安排起点为音频图时间 0.116 秒、终点 1.616 秒；`ended` 回调时 `currentTime` 为 1.616 秒。约每 50 毫秒采样输出时钟，33 次观测单调，最后一次报告输出时间 1.637334 秒，超过安排终点；关闭前状态为 `running`，关闭后为 `closed`。页面报告 `outputLatency` 为 0.016 秒，但该值是估计量。`ended` 回调到采样首次越过终点的间隔受采样频率和调度影响，不能当成实际输出延迟。

中途停止中，安排起点为 0.110667 秒；停止请求时图时间为 0.661333 秒，而同次读取的估计输出时间为 0.640001 秒。`ended` 回调的图时间仍为 0.661333 秒；第二次输出采样报告 0.693334 秒，超过停止请求对应的图时间。两次采样单调，关闭前后状态分别为 `running`、`closed`。这些只是一个静音、本机、前台样本，不证明停止后实际输出了哪部分语音，更不证明听者听到了内容。

[Web Audio 规范](https://www.w3.org/TR/webaudio/)区分音频图时间与设备输出时间；[getOutputTimestamp 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)描述输出帧时间的估计，[outputLatency 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/outputLatency)也将输出延迟描述为估计。它们可作为未来明确采用 Web Audio 播放路径的研究线索，并非对现有 WebRTC 远端音轨或人耳实际听见内容的证明。还需覆盖可听音频、设备和输出切换、暂停及后台、调度误差、流式片段边界，以及与模型时间戳的对应关系；真实可信退出和上游费用也仍是独立问题。当前没有接入产品、播放账本或上下文截断确认，不改变语音准入。
