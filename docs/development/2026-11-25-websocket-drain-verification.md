# WebSocket 尾句收尾与插话停播验证

2026-11-25（Asia/Shanghai）。继续使用北京地域 `qwen3.8-omni-flash-realtime`。正式练习页仍在隔离配置验证，使用 Chrome、临时 PostgreSQL 17.11、合成英语和静音输出。

## 正式结束与插话

- 正常结束立即释放麦克风和播放音源，发送独立收尾帧。服务端拒绝之后的音频、重新开麦和新回复，排队但尚未交给上游传输的回复请求也会丢弃。服务端自收到帧起最多等待 5 秒接收 `stop`，客户端仍使用原 3 秒截止。已经交给上游传输的请求可能完成，仍按原会话归属处理。
- 对已登记且未停说、未提交的用户项，服务端最多发送一次明确的输入提交，只收同一项的最终转写。已登记助手回复的匹配首项和最终文字可在收尾期送入；助手失败终态不冲掉用户尾句。用户转写失败保留缺口，已登记助手文字仍可到达，供应商错误正文不下发。
- 插话隔离以旧音源成功停止和断开为准。没有输出时钟时仍可停播并保存用户插话；音源释放失败继续关闭传输。播放证据保持 `unknown`，不据此推算已听文字或开启续聊。Chrome 的无时钟场景隐藏了 `getOutputTimestamp`，仍观测到停播、中断界面和三条封存转写。

## 真实千问

| 路径 | 实测结果 |
| --- | --- |
| 停止发送与单次显式提交 | 28 帧合成语音结束后，3 秒内没有供应商最终转写。随后发送一次提交，约 373 毫秒收到同一已开始用户项的最终文字。收到 `committed`，期间没有 `speech_stopped`，未请求回复。 |
| 对照自动提交 | 用 12 帧静音补足结尾时，VAD 返回 `speech_stopped`、`committed` 和最终文字。已自动提交后另发一次空缓冲提交的对照，3 秒内未收到新提交或错误，也未触发回复。正式路径在已停说或已提交时省略该命令。 |
| 正式练习页 | 从首页进入通话，实际传出 29 帧音频。点击“结束并复盘”立即停轨，发送一次提交，约 350 毫秒后收到原用户项最终转写。没有生成请求或助手回复。数据库封存一条用户转写，页面可查看保存情况，远端终止仍为 `unknown`。 |
| 同一次练习的会后复盘 | 从上项实际封存记录派生一条可评价输入，生产复盘 worker 调用真实千问文本模型一次，结果为有效空建议。落库记录为输入 645 Token、输出 5 Token。Chrome 从本人复盘地址打开和刷新均显示“本次未整理出建议”，共两次读取复盘、零次写入，数据库仍只有一次模型尝试。初次测试驱动使用了路径地址，改用应用的哈希路由后复验通过。 |

工作空间专属域名的 IPv4 直连在 TLS 握手时重置，IPv6 使用相同官方域名和证书验证成功。隔离联测显式使用 IPv6，标准网关地址、域名校验及默认配置沿用原配置。此次真实语音实验无回复生成请求，实际账单未核。真实语音确认后的关闭码为 `1000`，远端释放及停费仍需供应商证据。[百炼实时语音接入](https://help.aliyun.com/zh/model-studio/realtime) · [客户端事件](https://help.aliyun.com/zh/model-studio/client-events)
