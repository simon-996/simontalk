# 千问实时上下文与语音轮次控制实测

日期：2026-10-28。用户授权既有千问配置的针对性实测，首轮累计上限20元；使用北京 `qwen3.8-omni-flash-realtime`，没有切换正式语音供应商或开放准入。全部文本为合成测试数据，语音由本机 Samantha 离线合成；不采集麦克风、不播放或保存模型输出音频。[脱敏逐次证据](evidence/2026-10-28-qwen-context-vad.json)。

## 删除与重建上下文

| 实验 | 实测与解释 |
| --- | --- |
| 删除已生成项，再插入助手文字 | 真实生成项收到匹配的 `conversation.item.deleted`，随后 `conversation.item.created` 回显了期望的助手角色和文本。两次插入均返回了不同于请求指定的服务端ID；首轮探针因此主动判失败并关闭，未做后续推断 |
| 读取新项 | 使用返回的实际ID尝试 `conversation.item.retrieve`，收到 `invalid_request_error/invalid_value`、param `type`；不能通过本次查询核对模型上下文 |
| 固定词对照 | 删除与插入后模型仍提到旧词，但初始用户提示也包含该词，不能作为旧回复残留证据 |
| 删除原用户消息的正负对照 | 不删除助手项的对照和删除/重插组都回答 `NONE`；正对照未检出原内容，不能拿这组判定删除效果 |
| 保留原用户消息，模型自行生成六位数 | 对照组复述其生成的 `739152`；删除原助手项、插入不含数字的文字后，另一组仍复述该组原生成的 `739104`。原用户提示没有给出这个数字。这是一次可疑的旧信息延续，仍不能完全排除模型猜测或内部实现差异 |
| 改变替代文字的颜色 | 对照组复述原颜色和数字；处理组的替代文字是绿色且无数字，模型却回答蓝色及一个数字。该数字与它原先生成值不同，所以只能认定本次回答未遵循替代文字，不能宣称保留了该原数字 |

这些结果说明：**删除和插入事件的确认不足以证明后续模型上下文已按精确前缀重建**。事件ID回显差异和实测回答也说明不能仅根据请求发送或事件类型解锁原有 `confirmContextTruncated`。两项控制实验覆盖的是文本模态、串行操作及少量样本，不是所有时序或型号的统计结论。

## 新会话中的回顾

新会话内，空上下文对照回答 `NONE`。插入一条服务端确认的助手文本“The lantern is green. The animal is zebra.”后，下一轮仍回答 `NONE`；两组输入用量均为60文本Token。这次观察不足以证明所有助手项都被忽略，只说明创建确认和模型可用上下文不能画等号。

另一组新会话在用户消息中明确写“Previously you said: The lantern is green. The animal is zebra.”，再询问先前内容；空对照回答 `NONE`，回顾组回答绿色和斑马。该次是模型读到用户侧回顾文字，不等于原助手角色或音频上下文被恢复；回顾文本的来源、注入防护、跨账号隔离、重连和旧会话退出均仍需验证。

## 音频与文字时间关系

一次固定句语音输出返回349,440字节PCM，仅内存计数；六段文本delta均在第一音频包之前到达，首段文字约0.754秒、第一音频约1.074秒。该观察不是设备播放时间，文档所列事件没有提供逐词播放时间。不能根据文字delta、网络到达顺序或字节比例猜测已听前缀。模型返回的语音和文字Token分别计费；[官方事件参考](https://help.aliyun.com/zh/model-studio/server-events)。

## VAD 关闭自动生成

一次WebSocket会话发送 `server_vad`、`create_response:false`、`interrupt_response:false`，收到同值配置回显。上传3.580秒合成英文及2秒静音，收到speech_started、speech_stopped、committed和准确的最终ASR；停止后4秒观察窗口内未收到 `response.created`。随后明确发送一次 `response.create`，收到completed及用量。数据上传以100毫秒块发送；事件时间是探针读取时间，不能作为服务端精准发生时间或设备延迟。

另一次试验在AI已开始输出后送入同一合成音频；接收器在收到967,680字节后超过960,000字节上限并退出，后续等待超时，未获得 `response.done` 或usage；本机发送1000关闭帧但未收到远端关闭帧。只观察到speech_started时原回复尚未结束，**不能判定自动取消或第二回复行为**。探针没有在接收器超限时立即发送取消，这是实验本身的缺陷；不可将空回执或本机关闭当成远端释放/停费证据。后续新增仅接收已打开连接的本地诊断流程：`scripts/qwen_overlap_probe_guard.py` 负责上限、事件和单次取消；`scripts/qwen_overlap_probe_supervisor.py` 同时监督输入与接收，记录输入是否完成并按服务端实际响应ID核对事件；`scripts/qwen_overlap_probe_session.py` 串起配置回显、固定合成提示、单次回复请求、重叠观察与本地关闭帧记录。它们不自行连接、不读取配置、不生成或播放音频；调用者仍须提供隔离连接与合成PCM，也必须按结果逐项检查，不能仅看外层函数返回。26项本地替身测试及Ruff检查通过，覆盖上限、异常、外部取消、无关/缺失响应ID、语音结束观察窗口、额外回复、配置或输入项未确认、响应创建超时、输入非法及关闭帧缺失；若额外回复被取消后没有终态，它的用量和退出仍未知。

这些测试证明本地代码在所模拟的事件顺序下作出的行为，**尚未使用这个流程进行真实复测**，也没有完成连接创建、真实合成音频生成/装载和结果落盘的可执行入口或供应商协议复核。官方服务端事件文档列有音频delta的 `response_id`，但这个新流程尚未验证真实回显字段、并发取消、超时和关闭行为；收不到远端关闭或用量不能记为成功或零费用。原未知调用的账单和退出条件未核实前，不增加计费调用。

上述配置只在WebSocket和本次合成音频情形实测；WebRTC真实音轨、网络/设备及并发交错未验。[官方实时指南](https://help.aliyun.com/zh/model-studio/realtime)描述WebRTC使用VAD和RTP；当前结果不证明WebRTC端具备同等控制。

## 用量与影响

本轮共17连接、26次明确响应请求，25次有用量、1次重叠试验用量未知。已返回用量共输入文本2,340、输入音频28、输出文本338、输出音频91 Token；按[北京官方标价](https://help.aliyun.com/zh/model-studio/qwen3-8-omni-flash-realtime)估约0.006291元。未知响应及此前缺用量调用不能记零，实际账单与剩余额度未核；20元为授权上限，尚无供应商硬停费实现。

官方[WebSocket接入概览](https://help.aliyun.com/zh/model-studio/realtime-websocket-overview)明确区分单次 `response.done` 与连接关闭，Omni结果接收后关闭连接；[Omni英文指南](https://help.aliyun.com/en/model-studio/realtime)所述刚连接即关闭可能耗时5–10秒是示例说明，不是完成时限或计费释放保证。不能把另一模型的 `session.finished` 套入Omni。

官方[费用概览](https://bailian.console.aliyun.com/cn-beijing/costing-balance/overview)可按模型、业务空间和API Key查看费用；本机Edge该页面显示未登录，故未读到账单。官方[预算管理](https://help.aliyun.com/zh/model-studio/budget-management)支持按账号、业务空间或Key设置自然月预算及达额停止，但停止可能延迟、统计范围有限，不能直接等同本次跨调用的累计20元上限，也未实际配置或验证。

本轮新增本地诊断流程及其测试，没有修改产品源码、依赖、schema或数据库；原有正式语音准入和unknown占用保持。下个可执行方向是修复有界探针并核实重叠时序，进一步验证新会话用户侧回顾的安全编码与可靠退出；只有满足实际播放边界、可信终止和业务链路要求后才能开放真实媒体。供应商询问稿仅更新，未发送。
