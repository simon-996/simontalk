# 千问 WebRTC 经产品媒体控制器单轮验证

2026-10-30 约 12:07（Asia/Shanghai），在此前用户授权的累计 20 元受控实验范围内进行一次连接和一次回复；不把此预算视为供应商硬停费。原工作区保留，未打开正式语音准入。

## 方法

Edge/macOS 的隔离页面运行 Flutter Web 编译后的仓库真实 `PracticeMediaController`、`QwenGuardedProtocol`、Dart Web 传输和 `web/realtime_transport.js`，一次 SDP 交换使用仓库真实 `QwenWebRtcSignallingGateway`，连接北京 `qwen3.8-omni-flash-realtime`。账号、练习和连接登记 HTTP 由本地 `MockClient` 提供，日志/持久化不在本次范围；实验不访问业务数据库或正式页面。观测包装器只计数事件、读取 usage 及检查最终投影状态，不向供应商增加消息。

实验页面将 `getUserMedia` 指向 Web Audio 虚拟媒体轨道，在控制器进入 active 后播放固定合成英语及静音共 5.5799375 秒；没有请求或采集物理麦克风，也没有使用真人语音。页面创建音频元素时设置静音。最多一次信令交换、一次明确回复请求、45 秒本地超时；模型回复终态后等待约 2 秒读取 WebRTC 统计并停止本地控制器，没有自动重试。脱敏页面输出为人工转录，见[证据](evidence/2026-10-30-qwen-controller-webrtc-voice.json)；未保存原始对话、音频、SDP、密钥或供应商会话标识。

## 结果

信令网关记录一次交换开始并返回；真实控制器配置确认后进入 active，未在配置中发送 `tools`。合成语音最终识别包含两个固定标记词；控制器的对话投影包含用户和助手两个最终话轮，助手播放证据仍为 unknown。只发出一次 `response.create`，收到 `response.done` 且状态 `completed`。

结束前一次入站音频 RTP 统计为 213,081 字节，控制器的播放器观察为 `waiting`；随后控制器本地关闭，释放状态为 `unconfirmed`。入站字节和静音播放器都不能证明人耳听见，也不能推断文字播放前缀；本次等待状态的具体原因没有查明。测试记录的 phase 是停止前快照，localClosed 是停止后单独检查。

实际返回 usage：文本输入 726、音频输入 28、文本输出 21、音频输出 74，共 849 Token。按[北京公开价格](https://help.aliyun.com/zh/model-studio/qwen3-8-omni-flash-realtime)每百万 Token 分别为 1.5、6、4.5、12 元，已返回部分估约 **0.0022395 元**；实际结算、免费额度和其他费用以账单为准。

## 边界

这次比协议独立探针多覆盖了真实控制器和生产浏览器传输的事件链，但练习服务为替身，用户输入为合成音频，音频输出被静音，且只覆盖单轮。它不证明正式页面、真实设备播放、自然多轮/插话、上下文截断、异常断线远端释放或完整保存流程；mock 的连接响应也不能作为远端终态证据。正式语音入口保持关闭，下一步应针对播放器 `waiting` 与真实设备输出进行受控排查，并继续解决可信退出及多轮上下文。

后续本地回环定位到空流先绑定的问题并修复，见[音轨绑定验证](2026-10-30-webrtc-audio-stream-binding-verification.md)；本次千问实验使用修复前脚本，修复后的脚本尚未在供应商上复测。
