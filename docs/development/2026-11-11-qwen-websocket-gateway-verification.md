# 千问服务端 WebSocket 连接候选

2026-11-11（Asia/Shanghai）。新增默认不注册的服务端连接候选 `QwenWebSocketGateway`。配置固定北京 workspace 和 `qwen3.8-omni-flash-realtime`，检查 provider、region、model、config_id 精确一致；构造及配置检查不发网络。每个 attempt 最多发起一次握手，禁用代理与压缩、限制入站消息和队列、使用有界发送和关闭、禁止重定向；不创建下游 API、不修改正常语音准入。

连接只接有限长度、UTF-8 JSON 对象及有效事件名；二进制、畸形/过长数据和重复 JSON 字段失败关闭。并发读或并发写会中止本地传输，不能继续使用；取消/超时时关闭或 abort 本地连接，不自动重试。握手调用按独立截止返回；若被取消或超时的底层连接稍后仍返回 socket，后台只会有界清理，不交给调用方。关闭使用一个可并发等待的任务，调用者取消不会取消清理；迟到 I/O 结果被丢弃，错误不包含原始数据。由于底层网络库和操作系统行为仍有边界，本地关闭/abort 不是供应商终止确认，仍保留 unknown。

## 发现并修复的两处凭据风险

实际本机双端口测试使用仅用于测试的假 Bearer：`websockets` 15.0.1 默认连接器收到 302 后会向另一端口再次握手并转发 Authorization。新连接器拒绝所有重定向，测试确认重定向目标未收到连接。该库在 DEBUG 级别还会记录握手头与数据帧；新的私有连接器强制使用禁用的独立日志器，本机收发假标记测试确认即使宿主指定 DEBUG 日志器也不会记录这些标记。锁定 `websockets==15.0.1` 并用真实库回归，避免依赖内部行为无声变化；两个已有千问命令行探针改为使用同一连接器。

重要历史更正：此前部分 WebSocket 探针使用该库默认连接器，尽管旧报告写了“不跟随重定向”，其代码并未实现这一保证。本次本地测试证明默认行为存在风险；旧实测证据没有记录完整握手链，**无法据此判断当时是否发生重定向或凭据泄露**，不宣称已经发生或没有发生。此前实测期间的 debug 日志状态也未独立核实。本报告保留原始证据，并修正相关历史报告的解释。

## 验证

先用本机替身复现配置不匹配、单次尝试、取消/超时后迟到 socket、发送/关闭协程忽略取消、重复字段、后台关闭异常、并发收发和 DEBUG 日志问题；修补后相关测试通过。实际千问两次单连接验证：首次收到目标模型 `session.created`；第二次经新候选发送 `session.update`，收到同一会话的 `session.updated` 并核对型号、输出 PCM 24 kHz 与 max_tokens。两次都不申请麦克风、不输入音频、不请求回复；只记录布尔状态，不记录密钥、会话 ID 或原始事件。见[建连](evidence/2026-11-11-qwen-websocket-gateway-live.json)、[配置](evidence/2026-11-11-qwen-websocket-gateway-config.json)和[第二次探针源码](evidence/2026-11-11-qwen-websocket-gateway-config.py)。均未返回 usage，实际账单及远端终止状态未知。

Python 锁文件只新增 `websockets==15.0.1`；独立定向回归、Ruff、格式和 `uv lock --check` 结果见 HANDOFF。当前本机 PostgreSQL 测试服务未启动且桌面锁定；未在本轮执行数据库相关全量测试。正式代码默认网关、客户端到后端鉴权传输、音频采集、对话上下文及上游可信终止仍未接入，产品准入保持关闭。
