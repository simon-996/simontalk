# 本地 PCM 分片播放验证

2026-10-29。新增的 [分片播放单元](../../apps/client/web/streaming_pcm_output.js) 将 PCM16 小端分片转换成单声道 AudioBuffer，按采样率顺序排程，并在停止时冻结浏览器输出时钟估计；接口及限制见[设计](../superpowers/specs/2026-10-29-streaming-pcm-output-design.md)。这是未来受控流式音频路线的底层单元，尚未接入正式页面、供应商、现有 WebRTC 或播放证据。

10项 Node 本地替身测试覆盖双分片顺序、空隙、PCM 解码、停止与迟到分片、两种时钟倒退、暂停和无效时钟、分片和排程上限、排程异常，以及一个释放失败时仍释放其余节点。新增释放失败、上下文暂停与时钟倒退测试均先出现预期失败，随后修复并通过。替身不能证明浏览器、系统音频或真实设备行为。

三轮实际 Edge/macOS 本机浏览器测试使用临时 loopback 页面，两片各0.5秒的16 kHz、低振幅合成正弦波，仅在内存生成；没有麦克风、模型调用或文件音频保存。前两轮完整估计均为1秒，中途停止分别为0.286239及0.336001秒，冻结后不变并拒收迟到分片。最终代码新增状态监听及时钟检查后，再各做一次：完整估计1秒、中途停止估计0.336001秒，200毫秒后冻结值均不变且拒收迟到分片；主动暂停上下文再恢复时，停止估计为未知，恢复后仍未知且拒收分片。各次关闭后为closed。数值由页面可访问性文本人工转录，页面显示用户代理 `Edg/155.0.0.0`，不是准确安装版本。临时页面、服务和标签已清理。

这些观察仅说明页面读到了上述浏览器估计及显式暂停后的状态，不证明设备实际输出、听者听见、真实语音内容、各词时间或停止时音频已完全排空。没有测试设备切换、后台、网络流、真实模型音频、TTS词段对齐或多浏览器/手机；不能用该单元解锁播放账本、上下文或unknown连接。可信上游退出与费用仍是独立未解问题。

## 后续排程时序修补

继续检查时发现原实现先采样图时间，再转换 PCM 和创建节点；若准备过程耗时，`start`可能收到过去的时间，而估计依旧从旧时间累加。用替身分别模拟准备耗时250毫秒和`start`执行期间图时钟越过计划起点，两项均先失败。现改为准备后读取图时钟并预留50毫秒；`start`后发现已越过起点则终止且估计未知，准备期间停止也不会启动新节点。最终 Node 全量71项通过，含本单元13项。这只证明模拟时序处理；当时本地浏览器控制被禁用，因此该次修改时未在实际浏览器复验；上述三轮页面证据只对应修改之前的版本。后续当前版本的浏览器复验见下一节。此修补不改变准入、播放账本或可信退出状态。


## 排程修补后的浏览器复验

后续浏览器控制可用时，在 Edge/macOS 用 loopback 页面复验当前源码（SHA-256 `36c9851d79e3b64f8ad00263a2066e5cf385e8ae7008867fa53f02e074085e7c`，与页面加载副本一致）。一次按钮触发的本机低振幅合成正弦波，无麦克风、网络音频、模型调用或音频文件保存。两片各0.5秒，完整排程成功，估计及停止/200毫秒后冻结值均为1秒，停止后拒收新片；第二次两片排程成功，400毫秒后停止估计0.3286676666666666秒，200毫秒后保持不变且拒收新片；另一次排程后暂停并恢复 AudioContext，估计为未知且拒收新片；最终上下文closed。以上数值由页面可访问性文本人工转录。页面和临时服务已清理。

这补充当前版本在一台浏览器的通常排程观察，未在实际浏览器重现准备耗时或启动时错过起点；这两个异常场景仍仅有 Node 替身测试。结果不能证明声卡输出、听见的声音、精确文字前缀、远端释放或真实通话，也不改变默认准入。
