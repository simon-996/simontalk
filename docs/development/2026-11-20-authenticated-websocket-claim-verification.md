# 浏览器握手与持久声明验证

新增未注册内部入口：对 Origin、Cookie、CSRF 和账号执行既有严格握手预检，再以该身份执行真实数据库声明事务；仅提交后返回身份及绑定练习、连接、实例和 epoch 的声明。它本身不读取网络首消息、不启动供应商；调用方必须监听断开并取消等待，取得声明后若无法启动主管，须按该声明补记 unknown。

数据库事务在工作线程里运行，协程超时或取消不能撤销已开始的事务。入口对在途事务和迟到收尾保留有界名额；事务迟到成功时按原声明写入 unknown 和 blocked 核验，再释放名额。异常只返回固定错误，线程或收尾失败不能宣称已完成终止，也不会重试供应商。真实锁竞争测试持有连接行锁，确认声明事务实际处于 PostgreSQL 锁等待，再取消协程并释放锁；迟到提交最终记 unknown，未启动供应商。另测提交后尚未移交、超时和收尾阻塞期间的容量保留。

使用本机现成 `postgres:17-alpine` 镜像启动一次性 PostgreSQL 17.11 容器，测试库为 `simontalk_agent_test`，仅回环临时端口 62220，测试账号、数据和 socket 均为合成；结束后容器自动移除、端口不再监听。11 项新增测试通过，包括错误 CSRF、账号、撤销、实例和重放，以及真实数据库连接到主管/消息泵后正常停止和运行中撤销登录；下游及供应商 socket 为本地替身。与既有数据库身份、声明、主管、unknown、握手和消息泵等共 **153 项通过、零跳过**；本轮两个 Python 文件 Ruff 和格式检查通过。

这不是正式 WebSocket 路由或真实浏览器、麦克风、供应商调用。读取首消息、连接断开的实时监控、已提交声明无法启动主管时的统一收尾仍需实际入口接线；模型、真实播放、上下文恢复、可信远端退出和费用结清未验证，正式语音准入继续关闭。
