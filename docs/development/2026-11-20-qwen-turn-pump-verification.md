# 千问单次话轮消息泵验证

消息泵是未注册的内部单元：由调用方提供已配置的上游连接及下游发送和关闭函数，组合受限 PCM 上行、单写入者、单次话轮策略和输出音频过滤。用户转写成功交付后才请求一次回复；新语音插话时先退休已绑定回复的输出，并并发发送隔离通知和一次取消。不会在本轮中为插话再次创建回复。

本轮检查发现，隔离通知已经失败而取消发送阻塞时，原实现等待所有并行任务或动作超时才关闭。定向测试先以 0.5 秒等待复现超时；现等待首个异常，并取消仍在等待的任务、关闭上下游。反向的取消失败而通知阻塞也有测试。此处关闭是本地失败处理；已在途发送不能撤回，迟到下游任务受数量限制并由调用方确保 socket 关闭后不可复用。

本地组合测试经过真实主管、真实安全连接包装、真实消息泵及其 PCM/话轮组件，使用合成身份、模拟身份复验和 unknown 回写、假 socket 与合成 PCM。验证了同一连接配置、PCM 上行、一次回复、PCM 下行、插话隔离和取消；另验证模拟运行期身份失效会关闭上游，使等待接收的消息泵关闭下游。两项组合测试并不验证数据库事务或真实网络对端。

验证结果：消息泵自身及主管组合 7 项通过；与单写入者、话轮策略、音频过滤/上行、PCM 帧和中继、配置门、安全连接、重定向、握手相关目标共 171 项通过；本轮 3 个 Python 文件 Ruff 检查和格式检查通过。测试未使用物理麦克风、真实供应商或数据库；未重跑无关客户端和完整后端测试。

先前记录的临时 PostgreSQL 当前 15429 端口未监听，相关 PostgreSQL 可执行文件及两条 Homebrew 临时链接均未发现；原临时目录只剩不完整子目录，本轮没有启动、删除或修改它。不能把先前数据库回归当作本轮消息泵与数据库组合的验证。

消息泵尚未作为主管的正式生命周期部件接入，也没有认证 WebSocket 路由、客户端播放隔离接线、已听前缀或多轮上下文恢复；实际使用时调用方须在退出主管上下文前关闭消息泵和下游。真实设备、上游终止及费用结清没有新增证据，正式语音准入继续关闭。
