# 按回复隔离 PCM 分片

2026-11-11（Asia/Shanghai）。为受控流式音频候选扩展既有 `streaming_pcm_output.js`：调用方显式绑定回复及消息项后，路由器只把唯一事件的对应 PCM 交给该回复独立播放器；旧回复已停止后，其迟到分片返回 `stale`，不会进入后续播放器。错误项、未知回复、重复事件、索引错误、畸形 PCM、并发/重入及输出释放不确定均关闭路由，防止隐式切换。回复、消息项不可重用，最多 64 个回复、每回复最多 256 个分片；标识只在内存保留。

Node 测试先因缺少路由器失败；实现后 20 项 PCM 定向测试及 90 项全部 Web JS 测试通过。macOS Edge 157.0.4341.46 本机回环页面使用真实 Web Audio、两个静音合成 PCM 分片：A 播放器停止后建立 B，迟到 A 返回 `stale`，B 成功接收，A 身份复用被拒，AudioContext 关闭；[脱敏记录](evidence/2026-11-11-response-pcm-browser.json)。页面只观察本地调度和身份，音量全零；不能推断人耳听到、声卡缓冲清空或实际供应商中断。Web release 产品构建通过（无 Wasm dry-run），该文件的构建、测试页副本与源码 SHA-256 一致。

该路由器是可复用的生产代码单元，当前还没有接供应商、客户端协议或产品页面；它不负责身份鉴权、Base64 事件解析、上下文确认、上游终止或账单，也不授权下一轮。下一单元将受控处理真实供应商音频事件，再逐步接入拥有明确安全边界的传输链。正式语音准入仍关闭；本轮未调用模型、物理麦克风或数据库。
