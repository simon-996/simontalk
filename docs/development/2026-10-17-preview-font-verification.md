# 组件预览字体与发现验证

日期：2026-10-17。沿用户持续开发授权，在模型/设备条件暂缓期间补齐工程底座；没有供应商调用或设备许可操作。

## 复现与根因

运行`flutter widget-preview start --web-server --offline`，本轮默认LSP发现了6个预览，生成注册列表与实际界面一致。此前“No previews detected”没有复现，原问题根因仍未确定，未修改SDK或注册生成文件。

新的可复现问题是字形：截图中预览标题、按钮文字不可见或显示方框，AX仍有对应文字；浏览器日志显示本地回退字体连续404。Previewer有独立main，不执行正式应用加载NotoSansSC的入口；应用作为依赖提供的字体资产又需要包前缀。只在卡片中注册Noto能恢复按钮/内容，但预览器外层默认Roboto的中文标题仍显示方框。

## 修复

- 六个`@Preview`使用公开的`previewWithFonts` wrapper，共用一次字体加载Future；等待时显示加载状态，失败有固定诊断，不显示未准备的子树或原始异常。
- 复用原有Noto长度/SHA-256校验，通过`packages/simontalk_client/`读取预览依赖资产；同一份验证后数据同时注册为NotoSansSC和预览器默认Roboto别名，恢复外层标题。
- 正式main继续无参数调用`loadAppFonts()`，原路径、字体族及摘要校验不变；导入组件不执行预览字体加载，不在产品中注册预览别名。没有增加字体文件、依赖或外部字体服务。

## 验证证据

先观察缺少gate模块的测试失败，再实现。两个gate测试验证未就绪不构建子树、成功后展示，以及失败不冒充准备完成。最终Flutter全量**43项通过**、Node**51项通过**、分析无问题、格式通过；Web release与字体完整性检查通过。独立只读复核无P1/P2。

真实应用内浏览器的冷启动截图确认预览器标题及卡片中文完整可见。实际搜索“麦克风”，两张许可失败/等待预览均可发现；浅色普通字号与深色200%字号的说明、按钮和换行可见，状态明确标注“组件预览”。另四张品牌/标题错误的浅深色预览均有实际发现与渲染证据。没有点击真实麦克风操作。

包前缀字体通过实际HTTP读取，与项目字体字节一致。预览器外层会先于wrapper构建，加载期间仍可能产生本地回退尝试；最终字形不依赖这些回退。不能据此声称预览启动零告警。

最终正式Web产物在本地7357重新打开，截图确认完整登录表单、中英文和深色品牌首屏正常。共享加载器的默认调用仍可用，没有借预览过程绕过正式入口校验。

## 使用与限制

在`apps/client`运行：

```sh
flutter widget-preview start --web-server --offline
```

访问终端给出的本地地址，等待`Done loading previews`；字体首次加载后查看六项预览。字体初始化或缓存改变后使用全局热重启或停止后冷启动。此版本SDK在连续源码更新时实测出现`pendingHotReloadLibraryNames is not iterable`，冷启动可恢复；未修改全局SDK，不承诺自动热重载稳定。

本轮生成的`.widget_preview`由工具清理，临时预览服务停止。预览只展示组件状态，不能证明物理音频、供应商语音、真实手机、大陆网络或读屏器验收通过。
