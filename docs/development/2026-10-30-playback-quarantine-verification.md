# 中断后旧音轨隔离门

2026-10-30。真实千问 WebRTC 观察中，回复 `cancelled` 之后独立音频分析仍有非静音采样，无法以回复终态或上下文确认推断旧音频清空，见[实测](2026-10-30-qwen-webrtc-interruption-verification.md)。此前媒体协调器能冻结已验证的输出前缀，但没有调用传输层输出压制；上下文确认后也可能继续接受新回复。此次补充保守的本地隔离门，正式语音准入保持关闭。

## 行为

- 协议调用 `freezeResponse` 时，仅对原确认通道、已存在的助手回复和不早于已知输出位置的边界操作；非正常结束的首次冻结在处理前同步调用 `holdPlayback()`，不关闭上行。不存在的回复不触发输出操作；设置失败立即关闭本地媒体。
- 在调用传输前先标记上下文未确认及输出受限，避免同步重入绕过门禁；压制期间忽略迟到播放观察，不让已在途的普通播放恢复或迟到结果覆盖暂停状态。用户继续播放不会解除压制。
- 原回复允许按既有受限通道发送一次去重取消；用户输入和原回复允许的尾部事实仍按既有规则接收。上下文版本确认与音频隔离是两项独立条件：即使上下文确认成功，协调器也不会因此解除输出压制或允许新回复。若协议仍试图发送普通控制或引入新助手回复，则以 `playback_quarantined` 安全关闭本地连接。
- 本次没有定义可释放的可靠音频边界，因此协调器在该连接上不提供解除此隔离的路径；正常 `end` 仍沿用已有同步停采停播及有限尾部，不改为等待本地输出。压制和本地关闭均不证明供应商端停止或账单结算。

该门只在适配器提供已验证输出边界并调用冻结时生效；当前千问候选并无该边界，遇到第二次语音仍按原单轮规则失败关闭，尚未接入自然多轮或插话。此改动不能证明实际设备停止出声、已播文字前缀、供应商上下文或远端退出。

## 验证

新增协调器回归先复现未压制、上下文确认后可生成、压制失败未关闭及同步重入四类缺口；另外覆盖未知回复不触发压制、旧播放等待/held 回调、压制期间可接收用户输入和单次取消、旧回复尾部与上下文版本、迟到播放观察不改变最近观察状态，以及同步重入再次冻结时失败关闭。测试使用真实协调器和替身传输/协议；先前的本机双 Peer 和真实千问探针分别验证传输原语及供应商事件，不能冒充本次协调器端到端通话。

本轮没有调用模型、启动浏览器或物理麦克风，没有修改后端、数据结构或依赖。最终 Flutter 全量 1521 项通过、10 项专用测试跳过；Flutter 静态分析、3 个 Dart 文件格式检查及 Web release 构建通过，构建传输脚本与源码 SHA-256 一致。未重跑无关后端全量；下一步仍需建立可靠的旧音频隔离/恢复边界和已播前缀，验证上游可信退出，再在千问协议和真实设备上接通多轮。
