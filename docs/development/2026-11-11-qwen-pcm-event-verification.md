# 千问音频事件到 PCM 播放路由

**后续安全核对：** 本次临时探针使用默认 WebSocket 连接器，未显式禁用重定向；证据未记录完整握手链，无法判断是否实际重定向。现已用本地假凭据复现默认风险并修复后续连接，见[安全验证](2026-11-11-qwen-websocket-gateway-verification.md)。

2026-11-11（Asia/Shanghai）。在已有限定单回复 PCM 播放和身份路由之上，增加 `appendQwenDelta`：仅接已由调用方确认来源的 `response.audio.delta` 对象，检查原回复、消息项、事件身份和零索引，限制单分片大小、严格验证规范 Base64 与非空偶数字节，再交给原有路由。错误、重放或冲突关闭当前播放；已退休的旧回复先标过期，不解码也不进入新播放器。数据只在内存，不记录文本、音频或标识。该函数不接收未认证连接、也不自行建立模型会话。

新增测试先因方法缺失失败，后覆盖真实 PCM 样本解码、错误 Base64/长度/类型、重复和错项、迟到旧分片、解码时重入销毁；PCM 相关 25 项、全部 Node Web 95 项通过，产品 Web release 构建通过（无 Wasm dry-run）。

在既有累计 20 元授权内，使用实际北京 `qwen3.8-omni-flash-realtime` WebSocket 一次连接、一次固定短文本回复，不使用物理麦克风。临时本机服务只允许一次调用、限制时长/事件数和音频字节，使用私有配置连接上游；模型回复的音频事件仅在进程和本机页面内存中流转，不写磁盘。收到完成回复后，macOS Edge 157 的真实 Web Audio 通过零增益节点接收同一回复的 4 个音频事件，合计 49,920 字节，4 个全部成功解码及排程，随后停止并关闭音频上下文。使用量为 694 输入、17 输出、共 711 Token；接口未留存细分，实际账单以供应商为准。[脱敏结果](evidence/2026-11-11-qwen-pcm-live.json)与[当次临时探针源码](evidence/2026-11-11-qwen-pcm-live-probe.py)可核对，后者不含密钥或原始音频。

该实验是在全部分片收到后一次性交给播放路由，且输出静音；不证明低延迟连续播放、真人设备听到、插话时旧声音已清空、实际播放文字前缀或供应商退出。实际用户媒体输入、已认证客户端到后端的 WebSocket 连接、完整上下文和服务端终止核验仍未接入；正式语音准入继续关闭。下一单元推进受约束的后端 WebSocket 候选及连接生命周期，避免把本地播放器测试当成端到端通话。
