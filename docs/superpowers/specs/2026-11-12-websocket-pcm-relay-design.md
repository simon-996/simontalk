# 受限 PCM 下行消息处理候选

在未来由主管持有且完成身份/配置确认的单连接中，浏览器只可发送固定 PCM 二进制帧和严格静音控制；绝不接受任意供应商 JSON、地址、账号或模型设置。本单元只处理已收到的单条消息，不建立路由、进行身份验证或读取麦克风。

初始静音 epoch 0。文本控制最大 1024 UTF-8 字节、严格 JSON 不重复字段，仅 `{"kind":"mode","epoch":递增整数,"muted":布尔值}`（与当前状态不同、epoch 恰好加一、上限 uint32）或 `{"kind":"stop"}`。收到 mode 调用已有 QwenPcmInput；收到 stop 封闭并关闭服务端上游连接，本地关闭不证明远端终止。二进制先严格按 PCM wire 解码并交给同一上行组件，其校验重放、当前静音/代数、16 kHz 帧、单次发送和上游速率。旧代迟到帧丢弃，不跨代发送。禁止并发处理、错误和取消立即失败关闭，异常只返回固定码，关闭由唯一任务有界执行。

为防止静音或旧代流量绕开上行限额，所有入站二进制均受持续 10 帧/秒、突发 6 帧及每连接最多 36000 帧约束；控制最多 256 次且单独限速。调用方仍须在 ASGI/代理层限制消息长度、先完成浏览器来源/CSRF/数据库鉴权和独立持久 claim，并在客户端消失、账号变更、任务取消或退出时触发主管保守 unknown。调用方还需负责 WebSocket 双向流控及 provider 输出筛选。本候选不声称端到端语音、即时静音或远端退出。
