# 千问单连接上行串行调度候选

音频上行和回复创建/取消可能从不同协程同时产生；现有底层 Qwen 连接主动拒绝并发写，直接共用会使合法通话失败。新增仅供服务端主管使用的有界串行调度器：单连接永远只有一个在途网络 send，输入只接受由 QwenPcmInput 生成的固定 3200 字节 PCM append 和精确 `response.create`/`response.cancel`；不接受客户端原始 JSON、其他供应商命令或目标地址。

音频等待队列最多 3 帧、控制等待队列最多 2 条；已开始的网络发送不可抢占，后续控制优先于等待中的音频，同类保持先到先发。所有等待数据在内存中有界，不写日志；队列满、非法消息、网络错误、调用取消或显式关闭均同步封闭调度器，拒绝新输入、对已排队请求返回固定错误并尽力关闭底层连接。一次在途音频可能已到达供应商，不能宣称关闭或取消撤回数据。调用方仍需把同一 serializer 交给 PCM 上行和话轮动作，约束取消/新回复权限，并在失败时由主管记录 unknown；本单元不注册路由或证明上游退出。
