# WebSocket 持久连接声明候选（设计，尚未实施）

目标是在任何真实上游 WebSocket 连接前，将该次连接意图与账号、练习、客户端实例、epoch、配置及认证会话绑定，并沿用现有租约、占用、未知退出和删除恢复边界。只持久声明、不开公开路由，也不从 claim 推定上游已连接、已停止或允许复盘。

现有 `realtime_connections.offer_digest` 与 `signalling_started_at` 不只是 WebRTC 字段：放弃准备、练习固化、终止检查和回填都依赖它们判断可能曾发起供应商操作。新 WebSocket 不能绕过这些证据，不能仅新增一张表后让旧逻辑误认为未连接。候选是在显式新增并约束传输类型之后，将原 `offer_digest` 保留为兼容旧数据的连接尝试指纹：原 WebRTC 值依然是 SDP 摘要；WebSocket 为服务端构造、带版本和类型域隔离的绑定摘要，不接收浏览器自报摘要。需要评估数据库迁移、既有数据、备份恢复以及所有读写点；不能静默改变已有指纹含义。

事务必须先以预检摘要和账号执行数据库身份锁与复验，然后按既有 user → practice → connection 锁序验证归属、实例、epoch、状态、租约、服务器准入和精确供应商配置，检查 attempt 未存在；服务端验证可用配置后，原子持久化类型、指纹、开始时间、negotiating 和 termination unknown，再提交。提交失败不得尝试网络；并发/重放不得第二次启动；外部调用不得持有数据库锁。一次提交后即使进程消失，现有租约与终止核验必须保持占用，不能推定实际已建连或已结束。重连和结果回写必须重新锁定并复验同一登录 session、用户、练习、连接、epoch 和指纹；撤销、租约到期、删除、并发结束或回复遗失统一 unknown 并安排终止核验。

持久声明与结果路径、模式迁移及回滚、旧 WebRTC 兼容、并发和所有失败窗口必须使用隔离 PostgreSQL 和真实迁移测试；在证明这些之前不注册、不开准入、不触发供应商调用。长连接运行期撤销/后台离开、上下行音频资源释放和服务端可独立核实终止仍须单独解决。

## 2026-11-12 兼容选择

检查发现备份和删除归档严格锁定当前数据库修订；为单一候选先做模式迁移会同时影响既有备份可验证性。该单元采用不改变 schema 的兼容方式：在现有 `offer_digest` 保存由服务端固定前缀、owner/session/connection/client/epoch 计算的 SHA-256 指纹，明确只用于连接占用/终止证据，绝不伪造 SDP。有效 WebRTC offer 有固定 `v=0` 开头，与该结构有域隔离；既有单次信令检查会拒绝在同一连接上重放其他传输。后续正常状态 reason 不是可靠的传输身份，二次核验通过该服务端可重算指纹，不推断供应商已确认。无论迁移与否，旧归档格式保持原样；新增代码必须有数据库回归覆盖所有释放边界和跨路径冲突。
