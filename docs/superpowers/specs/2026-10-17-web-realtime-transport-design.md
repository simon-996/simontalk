# Web 实时媒体传输层

日期：2026-10-17。依据用户最新的持续开发授权，工程取舍直接执行；真实供应商准入继续关闭。

## 范围与选择

下一步的产品目标仍是真实语音闭环。当前缺少模型权限和费用边界，因此先交付闭环所需的真实浏览器媒体适配层，再接供应商协议；不增加没有真实服务的练习页面。

比较三条推进方式：先实现后端连接登记，会把未知的上游终止语义固化到数据库；先做反馈和记录，会跳过语音风险；先实现媒体传输，可以直接验证权限、协商、通道与释放，并保持供应商协议可替换。采用第三条。

Web适配使用浏览器原生RTCPeerConnection，经dart:js_interop接入现有Flutter。现有本机麦克风检查也使用这个平台边界。原生构建暂停，本次不添加flutter_webrtc和原生依赖；原生恢复时另行实现同一接口。千问仍是候选，不代表已经选定型号。

## 责任与接口

- `web/realtime_transport.js`：真实WebRTC、音轨、双向DataChannel、播放器和资源生命周期。创建对象不申请权限、不建连。
- `lib/features/realtime/realtime_transport.dart`及平台工厂：Flutter可用的类型、信令接口和桥接；不解析模型语义。
- 信令由可信业务适配器提供`exchangeOffer`和`cancel`，本层不接收上游URL或密钥，不自动重试。SDP仅在内存中处理。
- `start`仅完成传输连接及至少一个开放事件通道。`activate(channelId)`必须由供应商适配器在配置确认后调用，才挂载真实上行。不能把SDP成功或通道开放称作模型就绪。
- 发送控制事件显式指定接收该会话事件的通道，支持服务端创建通道；不会把模型事件变成业务最终话语。
- `setMuted`只控制用户显式静音。AI播放不改变上行音轨。播放被浏览器阻止时提供显式`resumePlayback`，不假装已播放。
- `activate`在音轨挂载完成后返回，不等待远端首个音频包；播放器的`playing`、`playback_blocked`和`playback_waiting`是独立观察。显式恢复播放最多等待5秒，超时仅报告等待，晚到拒绝仍会通知；解码/播放器错误则释放连接。

## 失败与释放

申请权限、ICE/信令/连接和等待配置各有有限超时。停止、后台、pagehide、音轨结束、连接失效或控制通道失效均停止本地音轨、播放器和连接，取消信令并清理监听器/定时器。停止幂等，晚到授权或信令结果不恢复资源。重连使用新实例，不自动重试可能已计费的交换。

事件限长64KiB，发送缓冲上限256KiB，SDP限256KiB；无效JSON、结构和超限输入明确拒绝，不写日志。模型事件只转给适配器。资源关闭的观测仅表示本地关闭，上游终止/费用仍为未知，不产生零费用记录。

## 验证

先写Node测试，使用明确浏览器API替身执行同一生产脚本，观察缺失行为失败，再实现。覆盖配置前不上行、顺序变化、服务器通道、取消晚到、超时、后台、静音、播放限制、限长与清理。Flutter分析、测试和Web构建验证桥接编译；可用时另做真实浏览器本机媒体检查/本地双PeerConnection协商。替身、loopback和硬件结果分别记录，均不能证明供应商插话、转写、费用或大陆网络已通过。
