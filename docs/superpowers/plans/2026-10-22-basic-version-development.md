# SimonTalk 基础版本开发执行路线

> **For agentic workers:** 执行单元内使用 `superpowers:executing-plans`；只有用户或适用指令要求并行时使用 `superpowers:subagent-driven-development`。下列复选框用于追踪交付，不代表已经完成。

**Goal:** 先交付本人可以实际完成的普通练习：登录 → 个人难度 → 自由聊天 → 真实语音 → 结束保存 → 历史回看和删除 → 简单会后反馈。

**Architecture:** 复用现有账号、准备/连接、媒体协调、文字/播放证据、固化和复盘模块，补齐普通练习页面与历史管理。供应商协议留在适配层；页面只消费领域状态。每个单元单独形成规格、实现和验收证据，不重建已有底座。

**Tech Stack:** Flutter Web、Riverpod、go_router、FastAPI、SQLAlchemy/Alembic、PostgreSQL；版本沿用当前锁文件。

## 1. 如何使用

1. 完整阅读根目录 [HANDOFF.md](../../../HANDOFF.md)，检查 Git 状态与最近提交，保留未提交代码和文档。
2. 用本文件确定先后顺序；需求和决策看[产品总纲](../specs/2026-10-15-simontalk-mvp-design.md)，行为看[交互规格](../../design/2026-10-15-screen-and-interaction-spec.md)，接口以对应技术契约为准。
3. 每次只展开一个能交付的单元；先核对现有实现，再写该单元的具体规格和编码计划。已经有规格、计划的能力先复用，不重复设计。
4. 单元完成后把结果和证据写回 HANDOFF；本文件只更新执行清单及顺序，避免复制测试数量和即时状态。

本次文档整理没有启动付费调用、提交、推送或部署；持续开发授权与暂缓输入沿用 HANDOFF。

## 2. 本轮边界

| 本轮优先交付 | 本轮之后继续 |
| --- | --- |
| 已有账号与个人难度接入普通练习 | 少量日常话题入口 |
| 一个明确的自由聊天入口 | 英文开头、逐句翻译等独立辅助生成 |
| 自动接话、自然插话、静音、结束 | 一级重练客户端与改善评价 |
| 最终文字保存、保存状态和失败处理 | 重练关联回看等完整学习体验 |
| 本人历史列表、详情和删除 | 更丰富的伙伴、动效与长期学习积累 |
| 原话可定位的零至三项会后反馈 | 原生构建与分发，恢复时单独验收 |

这是交付顺序调整，不删除 R04/R06/R08 等原首版需求，也不把基础版本完成写成完整学习闭环或朋友可稳定试用。新页面不添加尚未接通的占位操作。

账号隔离、明确错误、幂等、媒体释放和用量来源随功能交付；基础版本不降低既有数据、身份和终止约束。字幕显示、麦克风静音与难度快照分别处理，沿用原规格。

**工程入口：** `apps/client/lib/features/realtime/`、`apps/client/web/realtime_transport.js`、`features/practice/`；后端 `signalling.py`、`practice.py`、`config.py`、`main.py`、`termination_checks.py`。具体供应商文件及 API 在准入核查后单独命名和定稿。

- [ ] 核对供应商最新官方文档、账号地域/模型权限、允许费用、目标浏览器及真实设备；记录候选能力和待验证项。
- [ ] 先验证可信终止/可信失效与客户端消失后的占用退出路径，覆盖信令答案丢失；没有退出证据时维持默认关闭，改评估其他媒体路线。
- [ ] 按已验证路线接入后端网关和客户端事件适配；长期密钥只在服务端，初始传输连接与模型配置确认分开。
- [ ] 练习页展示真实连接/听取/思考/播报/静音/异常状态；只有媒体和协议实际就绪才能显示正在听取。
- [ ] AI 播报时保持上行以支持自然插话；核对停播、旧生成取消、实际播放上下文和最终转写，不以按钮取消替代语音插话。
- [ ] 结束立即停麦停声，复用有界收尾、固定补交、固化和回执；分别显示内容保存、本地释放及上游终止状态。
- [ ] 真实验证权限拒绝、建连失败、业务后端失联、断网、后台、重复结束和账号变化；未核验终止的连接继续阻止新建。
- [ ] 对照供应商来源记录用量和费用；未知用量不填零，客户端时长不冒充结算或硬上限。

**退出标准：** [验证计划](../../validation/2026-10-15-validation-plan.md) G2 对应证据、实际设备/网络及媒体退出证据齐备；完整记录成功和失败。不因先聊通一轮跳过正常准入要求；仅技术实验时需要另行明确其受控边界。

### B5 简单会后反馈

**工程入口：** 后端 `review_gateway.py`、`review_jobs.py`、`review_input_policy.py` 与 `review_worker.py`；客户端复用 `features/review/`、`features/transcript/` 和现有 wire 测试。

- [ ] 输入齐备后接真实文本模型，沿用固定输入、引用门、持久任务和有限重试，不另建一套反馈系统。
- [ ] 验证成功、无可评价内容、有效零项、模型超时/格式错误/非法引用、明确重试与重启恢复。
- [ ] 抽查真实原话、原意、建议理由及纠错/润色区分；不编发音分数、不凑建议数量。
- [ ] 阅读已有反馈与原话不重新调用模型；任务未知调用按既有约束保守处理。
- [ ] 把独立反馈用量计入真实来源并验证删除期间晚到结果不能回写。

**退出标准：** 工程链路、真实生成和人工语义抽查都有证据；重练入口等待后续可用时再接，不放占位按钮。

- [ ] 复核实际用量来源和已证明的终止/限额能力；费用硬上限是否必需仍按用户输入决定。
- [ ] 集成前核对全部变更归属，按现有授权处理本地提交；推送/部署仍需对应授权，不因文档整理自动执行。

## 5. 暂缓输入与可独立推进的工作

| 输入或证据 | 在何时需要 | 缺少时的工作 |

| 实际浏览器工具可用 | 页面点击/导航验收 | 保留已保存文字页待补项，继续实现及组件检查；不可用不是通过 |

这些输入继续集中登记，不在每个工程单元反复索要。可信退出是正常语音准入要求，不能通过跳过费用硬上限来省略。

## 6. 验证与交接规则

命令及环境以[本地开发](../../development/local-development.md)为准。每个功能单元先运行能覆盖变化的目标测试，回归通过后再做对应全量检查；不为纯文档整理重跑应用构建或模型实验。

客户端变化的常规检查，在 `apps/client` 执行：

```sh
dart format --output=none --set-exit-if-changed lib test
flutter analyze --no-pub
flutter test --no-pub
node --test test/web/*_test.mjs
flutter build web --release --no-pub --no-web-resources-cdn --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

后端变化的常规检查，在 `services/api`、确认独立测试数据库配置后执行：

```sh
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run alembic check
```

迁移变化另验降升、已有数据保留、metadata 和必要查询计划。Web 构建后按本地开发说明核对字体完整性；真实浏览器与 Preview 需实际打开查看。真实 HTTP/wire 使用独立库与临时身份，用后清理凭证、数据和服务；缺少夹具的 skip 不记为通过。
