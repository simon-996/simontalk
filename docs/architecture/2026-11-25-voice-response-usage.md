# 语音回复用量观察

千问 WebSocket 已验证归属的 `response.done` 提供逐回复的用量证据。服务端记录输入、输出总量及文本、音频分项。缺失、非法及矛盾的分项按未知处理，明确返回的零保留。普通练习与重练按各自连接记录。

仅接收后端实际持有的上游连接事件。每条记录绑定原连接和响应 ID 的摘要，写入时再次核对账号、练习、连接实例、代次、配置及尝试摘要。一次上游终态最多保留一条记录，同一键的迟到写入不会改写原值。数据不含原话、音频、上游正文或原始响应 ID，删除练习内容时沿用原连接元数据的保留边界。

用量由每条连接的有界队列及两个专用写入线程处理。媒体连接关闭不等待用量写入，原会话容量仍保留至后台工作结束。数据库暂不可写时后台只记录脱敏失败。进程在写入前退出或断开前未看到上游终态时，数据库可能没有对应记录。各回复用量用于后续对账，账单金额、实际停费和整次练习的完整覆盖需要独立证据。

数据库从 `4f6a58cd2e32` 升级到 `56bd3c921ab4`，增加用量表。备份和删除清单工具兼容这两个版本，备份清单随同一快照写入实际版本。降级先取得用量表独占锁，确认没有记录才移除用量表。
