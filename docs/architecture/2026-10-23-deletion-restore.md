# 独立删除清单与离线恢复契约

日期：2026-10-23。对应D13、[删除契约](2026-10-23-practice-deletion.md)和[设计](../superpowers/specs/2026-10-23-deletion-restore-design.md)。这是人工停服恢复入口；没有后台自动备份、跨存储实时删除日志或自动隔离流量功能。

## 删除决定的保存

`practice_deletion_receipts`保留原账号UUID、目标UUID、请求key、范围hash、数量、删除时间及当时的连接待确认状态。新增`members` JSONB只含按UUID排序的`id/kind/parent`，既不保存原话、反馈、重练目标、配置，也不保存凭证。

成员独立保存，不从恢复库剩下的墓碑猜测原范围。账号和练习可能尚未出现在更早的备份中，因此凭据不依赖它们的外键；重放只补删除凭据，不补造账号/练习，访问权限仍由现有登录与owner门控制。成员ID及账号ID也是私有元数据，清单须独立保管。

迁移`4f6a58cd2e32`位于`3e5947bc0d21`之上。旧凭据按原账号、删除时间、目标/一级关系回填成员，核对原计数与范围hash；不完整即事务回滚并拒绝升级，维护者须核对权威库/独立清单，不能删除问题凭据绕过。新列非空并校验数组长度；有凭据时拒绝降级丢弃完整成员。旧的墓碑可见性拒降规则继续有效。

## 清单格式及导出

`deletion_archive_v1`要求显式版本、UTC导出时间、按删除时间/目标/key排序的全部凭据及canonical JSON SHA-256。凭据内每个完整成员范围验证原hash、数量、一级关系；跨凭据成员和owner/key不能重复。严格拒绝重复JSON字段、未知字段、非布尔状态、无时区时间及损坏摘要。上限32MiB、10万凭据、100万成员。

`export-deletions`使用REPEATABLE READ READ ONLY快照，要求唯一当前Alembic head。所有现存墓碑须被覆盖；清单成员若在库中存在，其owner、类型、父关系与删除时间须完全一致。恢复缺成员或缺账号的库仍会导出完整决定。空库导出显式空清单，不能以缺文件表示“无删除”。

文件仅接受绝对输出路径，以0600临时文件写入、fsync、原子排他创建目标并同步目录；已有目标拒绝覆盖。stdout仅输出数量与hash。摘要只能检测损坏，不能认证来源，也不能证明清单是最新版本；最新完整性依赖维护者停写、核对和独立保管。

## 预检及原子重放

`replay-deletions --input ...`默认预检，零业务行变化；`--apply --confirm-database <字面库名>`才可写。目标先停API、worker和所有写入，并迁移至当前head。命令不创建HTTP管理端口，也不负责停止其他进程。

先校验整个文件，再依序锁账号、现有成员和凭据，按原时间模拟单子/父范围。存在的成员owner/类型/父关系/已删时间不符、原凭据任一字段不符、普通父存在清单外仍可见子时，整体拒绝；不扩大删除范围。缺成员/账号只统计，不补造。全批预检完成后才清正文并保存完整原凭据，单事务提交；超时、锁冲突或失败整体回滚。

实际清除复用普通删除的`purge_practice_content`，保留unknown连接、blocked核验和无正文用量证据。已删除不代表上游已终止、计费已结清。重复执行保留原时间/key/hash，业务全行不变；恢复后再次导出不会丢失备份中缺少的成员决定。

## 运维步骤

详见[本地开发](../development/local-development.md#独立删除清单与离线恢复)。前提是得到覆盖全部已受理删除的最新权威清单。停止写入后导出，独立保存并核对；恢复旧备份到隔离目标库，迁移、预检、明确应用，检查正文不可读取、账号隔离及unknown占用后才允许恢复服务。

任何拒绝、缺少最新清单或来源不可信均保持停止服务。不能以跳过拒绝、直接开放旧备份替代恢复。凭据保留期限/自动异地备份/独立实时日志/完整成本核对仍待后续实现。
